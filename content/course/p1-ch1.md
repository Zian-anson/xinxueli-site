## 本课目标

看得懂一件产品由什么组成、桌面应用和网页应用是怎么回事、出问题时该找哪一层。这是后面一切的地基——理解了，才谈得上把话说清楚；学透了，大部分坎你自己就能过。

## 正文

### 一件产品的解剖图

任何一件产品（一个网站、一个 App、DSH）都由四部分组成：

1. **前端**：用户看到、能点的界面。DSH 里你打字、看回复的那个窗口就是前端。
2. **后端**：幕后干活的程序。DSH 收到你的消息后，是后端去调 DeepSeek 拿回复、去执行工具。
3. **数据**：记事本。你和 DSH 的对话记录、它的记忆，都存在数据层里。
4. **插件系统**：给程序装卸零件的接口。DSH 的每个本事（能读文件、能开浏览器）都是一个插件。

这四层记住了，出事就能认层：**界面显示不对是前端的事，功能不干活是后端的事，记录丢了是数据的事，某个本事没有是插件的事。**

### 桌面应用与网页应用是怎么回事

你每天用的软件分三种住法：

- **桌面应用**：装在电脑上、双击打开。比如微信电脑版。
- **网页应用**：不装，浏览器输网址打开。比如网页版微信。
- **手机应用**：装在手机上。比如微信 App。

关键差别是**程序住哪、数据住哪**：桌面应用的程序装在你电脑里，数据多存在本机文件里，不联网也有一部分能用；网页应用的界面每次从服务器传过来，你的数据多存在服务器上，断了网就没了。

为什么同一个产品常有两种版本？桌面版有图标有窗口、开机自启、能用系统权限（麦克风、文件夹）；网页版免安装，跟着网址走。

还有一个行业秘密：**很多桌面应用里面其实包着一个浏览器内核**（这种做法叫 Electron）。界面就是用网页技术做的，穿上原生壳。所以你会在 DSH 上看到——

### 用 DSH 印证这一切

DSH 是「同一份 Web 界面、两种住法」：命令行 Web 版住在浏览器窗口里，桌面版穿了 Electron 壳住在桌面窗口里。所以两边界面一模一样。

但注意两件事：

1. **各自启动各自的 Host**：Host 就是每个窗口背后的后端。两边的端口也各是各的，互不打架。
2. **数据共享，插件组合各是各的**：会话、记忆这类产品数据两边共享；但启用的插件组合、包是分开的（桌面版有自己的 profile）——**在一边装的插件，另一边看不见**。这是新手最常见的困惑，遇到就想起这句话。

出问题时先认层：打不开、更新失败，是壳的事；界面显示不对，是前端的事；模型不回话，是 Host 的事。

### 一次对话的完整旅程

在 DSH 里发一条「你好」，数据走了这一趟：你的输入（前端）→ 交给 Host（后端）→ Host 调 DeepSeek 的接口（API）→ 回复写进会话记录（数据）→ 显示在窗口里（前端）。每一步都看得见——第 4 章你会亲手改它的前端。

### 产品住在哪

- **自己电脑**：你现在跑 DSH 的地方，关机就没了。
- **服务器**：一台全天开着的电脑，产品放在上面别人才能随时访问。
- **域名**：服务器的门牌号，比如本站的网址。
- **部署**：把产品从你电脑搬到服务器并让人能访问的过程。第二部分你会亲手部署一次。

### 三个必会概念

- **API**：程序之间约定好的接口。DSH 调 DeepSeek 用的就是对话 API。
- **密钥**：一串证明「我有权用这个服务」的密码。调 API 要填密钥，**密钥不能发给别人**。
- **环境变量**：系统级的配置值。密钥通常放这里，而不是写死在文件里。

## 要点卡

- 一件产品 = 前端 + 后端 + 数据 + 插件，出事先认层
- 桌面应用和网页应用：程序和数据住哪不一样；很多桌面应用里包着浏览器内核（Electron）
- DSH：同一份 Web 界面两种住法；数据共享，插件组合各是各的
- 一次对话的旅程：前端 → 后端 → API → 数据 → 前端
